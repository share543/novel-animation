## 資料流

```
小說原文
   │
   ├─→ ① 人物設定檔 ──┐
   ├─→ ② 場景設定檔 ──┤（這些只填一次，全程沿用）
   ├─→ ⑤ 提示詞庫 ────┘
   │
   ├─→ ③ 旁白稿 → 配音（TTS）+ 字幕
   │
   └─→ ④ 鏡頭表 ──→ prompt = ①+②+③+⑤ ──→ 批次生成
          │
          └─→ ⑥ 素材索引 → QC → 剪輯 → 成片
```

## 唯一的鐵則

> **① 與 ② 的描述字串永不手改。**

要改角色設定，改一次，全案鏡頭的 prompt 自動同步。
改了設定檔又改了鏡頭表的第①段，兩邊就會打架，一致性立刻崩掉。

## 為什麼文件之間要綁這麼緊

這六份不是六份獨立文件，是**同一個資料結構的三個視角**：

- 工具裡 = 一個 JavaScript 物件 `S`
- 紙上 = 這六份 Markdown
- 生成時 = 組裝好的 prompt 字串

三者必須同源。工具匯出的 Markdown 就是這六份文件的內容 —— 你可以只用工具，
也可以只用文件，但不該兩邊各改一份。
